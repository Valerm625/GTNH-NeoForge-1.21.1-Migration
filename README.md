## 本阶段实现

- 从保留的本地工作区按版本锁恢复输入；恢复工具仅创建缺失文件、保留当前源码，记录历史兼容 JAR 与公开锁不一致并要求重新编译。
- 对两个用户 ZIP 做逐文件及内嵌归档审计。保留 master 与 2.8.4 的任务身份差异、大小写路径问题和资源哈希，不将来源审计计作迁移完成。
- 检索任务保留旧版可损耗物品的耐久匹配规则，同时继续检查其余组件。
- 合成任务的无 NBT 子集采用严格组件匹配，修正原先 fuzzy 匹配会额外接受命名物品的问题；忽略 NBT 模式单独保留。
- 狩猎任务保留精确实体 ID 与子类匹配两种模式，包括牛与蘑菇牛；只作用于显式标记的迁移任务。
- 新检查覆盖真实 Minecraft/FTB 物品匹配、两代游戏类继承和故意损坏负例。锁定 Sponge Mixin 已在隔离服务中将 **9 个注入应用到 7 个真实目标类**，通过 230 个方法的数据流检查；完整 NeoForge 转换链和游戏运行仍未验证。
- 多物品检索纯引擎保留槽位预算、进度锁定和离线成员；新增逐 UUID 进度 codec 与按原 task index 执行的纯提交规划器。codec 通过 3,748 项断言、1,811 次源对照、633 次真实 NBT 二进制往返；规划器通过 9,716 项断言、2,414 次源对照，验证 `9 gravel + 5 logs → 两任务完成且剩 3 logs`。两者尚未接入世界存档、游戏提交或任务导出；独立文件组合见 Phase 4。
- Phase 3 新增旧格式 typed JSON 读取器与任务身份 envelope 纯模型。读取器通过 **2,932 项断言、577 次固定源码对照、74 个拒绝案例**；envelope 通过 **4,857 项断言、1,017 次路由源码对照、567 次真实 NBT 往返、32 个整份拒绝案例**。27 项组合断言将真实 `0:2` 定义、合成进度和来源符号物品谓词连到规划器；`logWood` 仍未映射，世界存档导入与运行时均未完成；独立文件保存见下项。
- 现有明确标记的单物品检索任务新增库存时机适配：初始同步、主背包槽 9..44（含变空）入队，下一次 Pre tick 去重检测。它不等于多物品规划器已接入，事件总线、队伍及完整世界行为仍未验证。
- 矿石资源以锁定主线 GT5U `5.09.54.205` 重建基准：34 张基础 PNG 精确复制，另有 34 张明确标注为派生的透明次层。与 2.8.4 参考相比，7 张编码字节不同但解码 RGBA 相同；客户端着色、资源优先级及最终视觉仍未验证。
- 四份锁定源码归档的 `src/main/resources/assets` 资源冲突审计记录 **16,267 次出现、16,237 个唯一路径、30 组同路径资源（60 个候选，24 组字节不同）、0 组大小写折叠冲突**，7 项独立检查（含错误注入）通过。CoreMod 的 `src/test/resources/assets` 中两个测试 XML 不属于运行资源，不计入此范围。审计保留全部候选，没有选定覆盖赢家，不计作已迁移资产。
