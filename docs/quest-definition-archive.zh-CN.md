# 原始任务定义归档与世界绑定

此阶段把真实任务来源接到已有的原生加载入口。它保存完整定义、建立只读索引并核对世界绑定，不代表这些任务已经能够在新游戏中完整执行。

## 输入和产物

`build_quest_definition_archive.py` 先核对用户 master ZIP 的锁定 SHA256，再逐文件核对解压目录与 ZIP 中的 `config/betterquesting/DefaultQuests`。7806 个文件全部保留原始字节，包括3814个任务、章节、顺序及设置文件；原始物品身份引用 JSON 也完整存入归档。额外的720条普通物品映射只包含已有映射或显式原版解析结果，不把矿辞、NBT或未映射物品简化成替代品。

二进制格式 `GTNHQDA1` 使用大端长度前缀：文档路径、类型、任务UUID、原始字节与逐文件SHA256，随后是原始身份引用及精确旧ID/metadata到目标ID的索引。两部分分别计算摘要，整个归档再计算摘要。兼容JAR内的 `gtnh_migration/quest-definitions.pin` 锁定三个摘要。归档以内容摘要为文件名保存在服务器目录的 `config/gtnh_migration/quest-definitions/`，新版本保留旧文件。

本次归档为21338767字节，SHA256为 `cf0367344bfa10587719e9a919d04dfd2877fe1e5c2a96b24a4323e0fb7973dc`。原任务正文和完整归档留在本地忽略目录；公开源码检查点只包含生成器、读取器、摘要pin与验证证据。恢复时设置 `GTNH_MASTER_ARCHIVE` 或将原ZIP放在 `inputs/`，并按RESUME恢复其他既有本地输入；这仍不是干净克隆后的一键发布流程。

## 读取与绑定

`LegacyQuestDefinitionArchive` 检查文件大小、文件类型和读取前后的属性，验证整体、分段及每个文档摘要，拒绝路径越界、重复路径/UUID/映射、错误标记、超限、截断和尾随字段。对外返回原始字节的副本和不可修改索引。typed JSON读取保留完整原始输入；不能解码或任务索引不合法时产生诊断，不能把该任务部分注册成正常的进度结构。

真实3814个任务均能解码，当前进度目录识别3743个检索**子任务**，保留真实task index及要求数量。这是进度格式目录，不是已迁移任务数量。未知任务工厂仍完整留在原始定义里，不会伪造其要求数量；进度读取遇到未支持记录仍拒绝整份候选。

`beforeWorldLoad` 在取得原生保存作用域后读取锁定归档。已有世界账本先非创建式打开，再用归档的定义/身份摘要和目录核对 `verifyCurrent`，成功后才执行标记维护、房主恢复和离线事务恢复。失败沿用加载前隔离和不保存关闭协议。没有账本的世界只挂载只读定义，不自动创建账本。`definitions(server)` 只在服务端线程且加载准备成功后提供归档。

## globalShare修正

固定BQ源码中的 `GLOBAL_SHARE` 只在全局任务的领奖判断中参与判断。当前3814个任务中有2287个非全局任务设置这个标志，纯规划器此前一律拒绝，妨碍实际定义接入。现在保留原始标志，在非全局检测中按源码处理；全局任务、奖励共享、重复和其他未支持模式仍不能执行。新增对照用例直接执行固定源码提取的原始任务检测循环。

## 验证与未完成部分

本次归档检查通过23282项断言、26个拒绝案例；40份完整重建汇总检查通过。归档检查逐字节对照7806个真实源文件、解码3814个任务，检查原始 `logWood`、globalShare、数量、未知任务保留及真实task index。测试还包含合成世界账本创建/重开、错误绑定不改进度、原件防修改和格式拒绝。独立运行该检查使用 `test_legacy_quest_definition_archive.py`。

完整重建将生成归档安排在编译兼容JAR之前。归档读取器的测试类与最终JAR逐字节对照；原生入场审计检查加载归档、核对世界绑定发生在恢复写入之前。

尚未实现由完整定义构造真实物品提交计划的生产绑定器、队伍及前置条件授权、原生提交按钮、完成与奖励状态机和完整界面。客户端视觉、真实世界启动/加载及其他模组交互仍未验证。摘要与文件属性检查不构成恶意并发写入或断电持久性的证明；不得因此宣布整合包完整迁移。
