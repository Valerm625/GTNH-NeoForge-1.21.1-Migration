# 世界目录与任务账本绑定

本阶段实现 `LegacyQuestWorldStore`：将独立任务账本、原始进度归档、历史任务目录与所属世界绑定。文件组件自身不注册事件；现由[原生启动和加载适配器](player-admission.zh-CN.md)调用。离线恢复结果不能直接用作玩家登录许可。

## 布局和来源

固定布局为 `<world>/gtnh-migration/quest-world.bin` 与同目录的 `quest-progress/`。清单不保存绝对路径或任意可执行路径，因此整个世界移动后可以重开。单独错放其他世界的清单或账本会因原始字节不一致而被拒绝；完整复制整个世界仍被视为该世界的副本，这不是防篡改身份认证。

清单包含随机存储 UUID、定义 SHA256、身份映射 SHA256，以及解码账本所需的历史任务目录：所有 quest UUID 和每个任务的 quest UUID、原 index、factory ID、需求项数。首帧必须在原件归档的第一项保存清单原字节，身份为 `gtnh-world-binding:v1/<storage UUID>`。后续帧继续保留原件前缀，不允许第二个世界绑定来源，也不允许先有账本再补写绑定来冒充原始关联。

二进制格式使用固定 `GTNHQWB1` 头、两个 64 字节 ASCII 摘要、大端长度和 UUID 整数；quest 按 UUID 排序，任务按 quest UUID/index 排序。factory ID 使用严格 UTF-8，不替换损坏字符。未知版本、重复定义、非规范顺序、无效字段、截断及尾部额外数据均拒绝。清单上限 8 MiB，目录数量上限各 100,000，单 factory ID 上限 65,536 字节；超过限制保留输入并明确停止，不能截断或称为迁移完成。

这些摘要依赖上游已验证输入，不能由任意调用者给出相同字符串就声称任务语义正确。历史目录只用于重开和解释旧账本；新提交还必须核对当前可信定义及身份映射摘要、目录摘要。

## 创建与重新打开

`create(world, binding, catalog, initialState, sources)` 是显式首次初始化，必须由调用者提供已验证状态和原件，不猜测一个现有世界应当是空进度。它先校验输入，再创建全新专用目录；目录已存在时直接停止，保留其中全部内容。

持有账本排他锁后，先 force 临时清单并同目录原子重命名，再提交含清单的账本首帧。`open` 必须找到有效清单、已存在的账本目录和完整非空链；它不创建缺失世界、清单或账本目录，不把缺失首帧当成空进度。账本锁仍使用文件存储层的锁文件机制。

首次初始化在创建目录或发布清单后中断，会留下未完成状态并拒绝重开；当前没有自动清空或继续初始化。首帧发布后中断则能够重开原来的账本。此行为经过独立 JVM 强制退出检查，但不是机器掉电后目录项持久性的证明。已有账本依然不能识别外部整体回滚或删除连续尾帧的全部情况。

目录链中的符号链接、缺失目录及非正常文件被拒绝；元数据目录只接受固定清单、账本和已知格式的临时清单。读取清单时复核长度、文件身份和修改时间，挂载后再检查精确字节。符号链接分支本次没有执行测试，也没有对恶意外部文件系统写入者建立安全隔离。

## 原生提交与离线恢复

`LegacyRetrievalCommitCoordinator` 的两个公开原生提交入口，在保存保护内、首次提交前检查服务器世界和账本路径、打开账本的解码目录、清单及首帧。每次原生隔离检查也重新核对绑定。独立账本测试入口保留，不能因此绕过公开原生入口的世界检查。编译后调用位置经过检查，原生玩家代码仍未实际执行。

`recoverOffline(assertOfflineExclusive)` 只可在调用者持续排除整个世界及玩家文件写入者时使用。它读取持久待决记录中的来源，不能按当前服务器模式重新选择：

- `PLAYER_FILE` 只读该世界 `playerdata/<UUID>.dat`。
- `WORLD_PLAYER` 读取 `level.dat/Data.Player`，同时要求 UUID 镜像的 UUID、完整 Inventory 和事务标记一致。
- 决策前重新断言隔离、复核世界绑定和完整文件摘要，然后交给现有日志判定提交或取消。

恢复不写玩家文件，不修改世界 NBT；正常结束后再次调用不重复决策。不一致、缺失或损坏文件保留待决记录，不根据另一份文件猜测成功或退款。它不会同步已加载的 `WorldData`/房主缓存，不会修复未知镜像，也不会授权随后原生 load 使用备份。原生启动/加载调用点现已接入独立适配器，但缓存修复、模式变化处理、安全故障关闭及游戏验证仍未完成。

## 验证与仍未完成的部分

`test_legacy_quest_world_store.py` 通过 **91 项断言、7 个独立 JVM 中断/重开场景**，覆盖清单与原件保留、整个世界移动、配置与目录变化、外来账本、后补绑定、格式损坏、缺失首帧/目录、并发句柄拒绝、普通/房主提交与取消、镜像冲突及读回期间变化。使用临时目录、合成玩家 NBT 和真实 NBT/文件存储实现，没有真实玩家存档或游戏世界。

该检查及生产类与兼容 JAR 的逐字节核对纳入完整重建。任务完成、奖励、队伍、网络/UI、原生入场事件与完整游戏运行仍未完成；依赖闭合导出仍为 2/3814，不因新增存储能力增加任务迁移覆盖。
