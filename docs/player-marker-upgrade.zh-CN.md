# 旧事务标记的持久升级

`LegacyPlayerMarkerUpgrade` 将本项目旧 v1 事务标记移动到 `NeoForgeData.PlayerPersisted`，升级为 v2。事务 UUID、准备记录摘要、背包数量和其他模组字段保持原值。它迁移的是本项目内部事务标记，不是整个旧 GTNH 玩家存档的格式转换。

## 文件、缓存与恢复顺序

启动入口在普通库存事务恢复前恢复未完成的标记维护；普通恢复及房主缓存验证之后，再处理旧房主标记。玩家加载入口在创建来源凭据之前按实际原生来源处理升级。所有操作持有原生保存范围及世界账本锁；生产调用点已编译和审计，尚未执行真实原生生命周期。

持久化位于 `<world>/gtnh-migration/player-marker-upgrades/`：

- `blobs/<SHA-256>.gz` 保存升级前和目标文件的完整压缩字节，写入后不覆盖。
- `ledger/` 保存追加式维护记录，首帧绑定同一世界清单原件，每次意图绑定主账本的确切版本与摘要。
- 意图记录先于玩家文件发布；房主有 UUID 镜像时先发布镜像，再发布权威 `level.dat`，最后更新实际加载缓存并发布完成记录。

每次替换前再次核对世界、账本、全部文件与缓存。临时文件强制落盘后在同目录原子替换，随后严格读回并核对完整摘要。没有非原子降级路径；不修改 `.dat_old` 或 `level.dat_old`，不创造缺失的房主 UUID 镜像。原生缓存只更新自有标记的位置，保留缓存特有的其他字段。

重启后的文件必须逐个等于已归档的旧版或目标版，才可继续发布目标状态。普通玩家与房主分别覆盖归档、意图、文件发布、缓存更新和决策后的进程退出。已完成记录可以跨后续库存事务继续核验，不把历史标记错误套用到新事务。

遇到未知文件内容、缓存/镜像库存不一致、主账本变化、历史原件损坏或缺失，保留全部数据及待决意图并拒绝覆盖。该行为防止未经证明的数据丢失；未知冲突的完整修复仍是未完成工作。

## NBT 二进制保真

Minecraft 的 FloatTag/DoubleTag 普通相等比较会把不同对象中的 NaN 判为不相等；原生读取/构造器还会规范化负零，DataOutputStream 的浮点写入会规范化 NaN 载荷。

因此文件升级不将整个玩家或世界 NBT 解码后重新序列化。它解析命名字段的原始范围，移走旧标记、将标记版本整数改为 2，并在 PlayerPersisted 内插入该片段。其他字段的二进制表示、顺序、根名称、数组、负零与 NaN 载荷原样保留。维护记录重新打开时，也会按这个允许的二进制差异核验目标归档。重复的标记路径或标记字段拒绝处理。

压缩头和压缩字节可能变化；升级前完整 gzip 原件与目标 gzip 都留在不可变归档中。两份独立手写的 UUID/世界二进制黄金文件覆盖全部 NBT 数据类型、两种负零、正负 NaN 载荷、中文/空字符及非空根名称，并对整个解压后文档进行逐字节对照。

事务日志、加载凭据、世界镜像和提交协调器的关键 NBT 比较现在按类型和浮点原始位比较。日志来源序列化保留对象中仍存在的 NaN 位模式。这里没有解决负零在原生玩家加载/保存全流程中的规范化，也没有改变 typed JSON 读取器对未支持负零的保留原件并拒绝策略。
