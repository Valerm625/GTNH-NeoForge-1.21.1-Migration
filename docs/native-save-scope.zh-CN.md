# 原生保存许可与生命周期入口保护

`LegacyRetrievalSaveScope` 管理一次提交独占的服务器、玩家列表、玩家文件存储、世界存储对象以及对应规范化目录。`LegacyRetrievalNativeSaveScope` 负责把原生对象绑定到该范围；公开协调器入口现在先获取此范围，再执行保存协议。相同服务器、存储对象或目录上的另一账本不能重入。正常游戏在没有活动范围时继续原生行为。

原生入口检查所有保护Mixin的标记接口和服务器真实存储对象。缺少转换、错误存储对象、错误世界目录或非服务器线程不能开始提交。标记接口不能代替完整转换链验证，但可以阻止对完全未转换对象直接执行本桥接。

## 一次性保存许可

许可对应准确的操作和接收对象，只能由原生方法入口消费一次。固定父子调用点上的Redirect创建嵌套许可，并用finally清理调用栈。允许的调用关系如下：

| 父操作 | 子操作 | 原生调用位置 |
|---|---|---|
| 全部保存 | 玩家列表保存、区块/世界保存 | MinecraftServer.saveEverything |
| 玩家列表保存 | 单个玩家保存 | PlayerList.saveAll |
| 单个玩家保存 | UUID文件保存 | PlayerList.save |
| 区块/世界保存 | 世界标签保存 | MinecraftServer.saveAllChunks |
| 世界标签保存 | level.dat发布 | LevelStorageAccess.saveDataTag |

房主所在的IntegratedPlayerList在父类save之前更新缓存，因此同一次单玩家许可依次检查OWNER_CACHE、PLAYER_BASE两个入口。普通独立服务器只检查PLAYER_BASE。房主缓存入口只在client配置中注册，公共适配代码不硬引用客户端类。

保存回调不能再次消费已用许可，也不能开始新的根保存、调用错误的父子边、切换玩家接收对象或跨线程执行。即使原生方法或回调吞掉拒绝异常，范围仍被标记为不确定；外层返回时再次检查，不能假装保存正常完成。普通I/O异常自身不等同许可违规，仍由协调器按权威文件读回决定提交、取消或隔离。

## 已加入的原生入口

保护Mixin现有30个注入点，涉及MinecraftServer、PlayerList、PlayerDataStorage、LevelStorageAccess、ServerPlayer和客户端IntegratedPlayerList。除了上述保存方法，还在下列操作开始前检查活动范围或进程级隔离：

- PlayerList的加载、加入玩家、退出/移除、重生；玩家文件的原生加载与备份回退。
- MinecraftServer的tickServer、tickChildren及stopServer。
- ServerPlayer的tick、doTick、死亡、restoreFrom克隆和跨维度。
- 世界存储的close、deleteLevel、renameLevel。

固定NeoForge字节码中，fireServerTickPre早于tickChildren；所以只保护下一次tickServer不够，还必须防止本次Pre回调之后继续世界/玩家tick。玩家退出也会保存，不能用普通断线替代隔离。

这些是具体入口保护，不是针对任意模组代码的沙箱。正常保存回调仍会执行；它们对物品对象的直接修改无法由保存许可拦住。协调器新增决策前全参与者库存复核：任何已观察成员与规划后态或取消前态不一致，都保留待决事务并隔离，不覆盖其他成员的物品。

## 范围结束与恢复边界

正常结果完成文件、辅助缓存/镜像和全部观察库存复核，并发布账本决策后，协调器才释放范围。明确没有进入持久化的不带违规预检失败也可释放。未知结果、许可违规，或没有显式release就close的范围继续阻止匹配的原生入口；没有提供“强制清除”接口。

隔离目前仅保存在当前进程。没有把账本绑定到世界启动，也没有重启后加载前的待决恢复；直接调用journal.resolveFromWorldPlayer仍不证明缓存/镜像及全部成员一致。停服保护会拒绝可能保存不确定数据的原生停止流程，但完整故障处理、恢复界面和安全关闭流程尚未实现。不能把这里的抛异常机制当成已验证的玩家恢复体验。

规范化目录识别另一个同路径PlayerDataStorage实例，但没有操作系统文件锁，不能阻止外部进程、符号链接别名或模组自行写文件。原始包的队伍、完成、奖励、完整定义和物品映射、所有模组生命周期仍需接入和验证。任务提交入口尚未挂接游戏按钮或网络消息。

## 验证

`test_legacy_retrieval_save_scope.py`执行生产状态机，172项断言覆盖原生顺序模拟、房主缓存两阶段、多个玩家、取消只刷新玩家数据、重入、回调吞异常、另一账本/同目录对象、错序/缺失钩子、异线程及Exception/Error后栈清理。原生方法体使用显式回调夹具。

`test_native_save_scope_mixins.py`使用真实固定Sponge变换器，分别检查客户端和独立服务端字节码及Side配置。客户端为30处注入/6个目标/586个方法数据流检查；独立服务端为29处注入/5个目标/579个方法检查，后者不加载客户端类。另检查所有入口处理器先于原方法调用；缺失文件保存方法和漏注册保护Mixin两组破坏性负例按预期失败。它不定义或执行游戏类，也不是完整NeoForge ModLauncher转换链。

普通提交协调器检查增为168项，新增保存回调改动其他已观察成员的拒绝场景。真实Player、世界、客户端、原生事件执行和重启入场恢复仍未验证；这些新检查不增加2/3814的任务导出覆盖。


## 原生加载范围补充

新增[启动与玩家加载适配](player-admission.zh-CN.md)。保存事务中的加载仍被拒绝；独立入场范围只允许同一玩家经过 PLAYER_LOAD、可选 PLAYER_FILE_LOAD、PLAYER_NBT_LOAD。世界启动与正常停止也有调用点，当前隔离变换总数为客户端39处、独立服务端38处，新增缺失加载目标负例。原生游戏执行、故障停止和其他模组全部兼容性仍未证明。
