# 检索提交协调器与原生保存适配

`LegacyRetrievalCommitCoordinator` 把已有独立账本、库存桥接、标记和玩家文件读回串成一条提交流程。公开入口接受真实ServerPlayer及PlayerDataStorage，并调用原生saveWithoutId、getPersistentData和save；代码已针对锁定NeoForge server编译。测试通过包内保存接口注入故障，未实际运行ServerPlayer或原生保存方法。当前没有注册游戏事件或提交消息入口。

后续[存档来源审计](player-storage-authority.zh-CN.md)确认单人房主可能使用level.dat/Data.Player。普通submit在写入前拒绝isSingleplayerOwner；新增显式submitIntegratedOwner按世界来源处理，并核对缓存和玩家镜像。两种入口都未注册到游戏生命周期。

## 提交顺序

1. 校验库存对象属于actor、计划仍可使用、线程与所有参与者槽位未变、账本完整Head等于规划时快照，以及外层授权条件。不能只拿相同摘要包装不同的状态，也不能复用已经尝试过的计划。
2. 按已解决日志核对玩家标记，必要时将旧v1升级到PlayerPersisted中的v2。调用保存后读取对应权威文件（普通玩家UUID.dat，房主level.dat），确认库存和标记与内存一致；房主还须核对缓存与UUID镜像，再允许准备事务。其他模组的持久数据保持原样。
3. 用已确认的磁盘基线生成候选，追加准备记录。账本暂不提交新进度。
4. 重新检查基线文件及条件，应用实际库存计数，再只更改本项目的标记字段。调用原生保存接口；返回成功与否都不能替代读回。
5. 当前权威文件中标记和库存都与新候选一致，且内存也一致时，才提交账本进度；房主缓存与镜像也必须一致。保存器在发布文件后抛异常，仍以文件证据判断；诊断保留在Outcome中。日志使用来源绑定的文件Snapshot，并再次复核完整文件摘要。
6. 当前文件证明仍是旧状态时，先恢复本次扣减的原物品对象和数量，再恢复旧标记。全部内存与磁盘复核通过后才发布取消记录。普通UUID路径不改写文件；房主路径可能用玩家列表保存刷新已落后的缓存或镜像，但不保存level.dat，并要求该世界文件的完整摘要保持不变。

恢复已完成计数应用时，先检查所有参与者的40槽后状态，并预查每个原始物品对象。整栈移除后仍保存原对象引用；它在脱离库存期间被改动，也会阻止恢复。其他代码替换了槽位对象时，即使替代物看起来相同，也不覆盖它。没有全玩家NBT加载，没有按旧快照重写其他模组数据，没有发放奖励或广播UI。

## 不确定结果

无法读取当前文件、标记与库存不构成合法前/后状态、外部改动物品、账本写入结果不确定，都会保留现有文件及待决记录（若准备已发布），并让本次账本对象及参与库存进入拒绝再次提交的状态。正常保存方法吞掉异常但磁盘仍是旧状态时，可以按上述取消路径恢复；不可判断时不能猜测退款或继续扣减。

`RecoveryRequiredException` 要求调用层继续隔离玩家和写入。现在原生入口会获取[保存许可范围](native-save-scope.zh-CN.md)，在未知结果时保留范围，阻止已注册的保存及生命周期入口；这部分尚未在真实游戏执行。包内合成保存端仍只标记账本/库存。不能把普通断线当作隔离操作，因为退出流程可能保存不确定库存；进程级保护也不能代替重启后的加载前恢复，当前不能直接激活为联网提交入口。

新范围按服务器、存储对象和目录阻止跨账本重入，以一次性许可保护固定原生保存调用链；正常保存回调仍然执行。任意模组直接修改物品、外部文件写入、绕过原生入口的代码以及持久登录恢复尚未隔离，传入的assertExclusive仍负责这些未覆盖条件。房主适配器调用saveEverything，取消修复可能调用PlayerList.saveAll，因此要求覆盖整个服务器及其他玩家。协调器在决策前重新检查全部已观察库存，检测到回调改动不会发布进度。认证、原BQ入口条件、队伍校验及可靠故障关闭仍由可信调用层负责。


报告：`evidence/quests/LegacyRetrievalCommitCoordinatorCheck.json`。runner固定NeoForge server摘要，编译生产原生适配器；执行测试时使用真实原版Inventory(null)、ItemStack/NBT codec和本地文件，保存端及玩家数据为合成夹具。

普通路径168项断言、世界玩家来源47项检查、房主协调257项断言及4组字节码破坏性负例通过。原生保存许可另有172项状态机断言与独立Mixin变换检查。完整重建核对生产类及其嵌套原生适配器与兼容JAR逐字节一致，避免只测试未打包的实现。

覆盖正常提交、整栈/部分扣减、静默失败、发布前后异常、旧标记在准备前升级保存、重复提交、失去授权、跨协调器重入、旧Head/伪造Frame、错误库存对象和缺失隔离。拒绝损坏文件、仅新标记却旧库存、保存后的内存变动、外部替换栈及脱离库存的原对象被改动。账本准备/决策的临时文件强制写入及发布边界另有故障注入，关闭重开后按磁盘恢复，确认不会退款、重扣或改写玩家文件。

这不是新的独立JVM或机器掉电测试；既有日志的7个JVM中断测试继续保留。真实玩家存档fixture为0，原生保存/回调和世界生命周期未执行。OAK_LOG为测试谓词，不能替代尚未核实的旧logWood集合。
